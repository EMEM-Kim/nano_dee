# 4주간 학습 결과

주차별 교육 항목에 따라 SQL 학습부터 AI 활용 결과물 제작까지의 내용을 정리했다.

## WEEK 1 · SQL 학습

건강보험 청구 데이터를 대상으로 SELECT, WHERE, ORDER BY, GROUP BY와 JOIN을 학습했다. 같은 데이터에서도 명세서 수와 고유 환자 수는 다르므로, 쿼리를 작성하기 전에 분석 단위를 정해야 한다는 점을 배웠다. WHERE와 HAVING의 적용 시점도 구분했다.

결과물: [SQL 실습 1~5](../sql/practice/practice_1-5.sql)

## WEEK 2 · SQL 실습 및 결과물 정리

윈도우 함수를 사용해 환자별 방문 순서, 이전 방문과의 간격, 누적 진료비를 계산했다. 폐암 합성 데이터에서는 진단 시점별 코호트와 병기별 치료·사망 기록을 분석했다.

과제의 연도 조건과 같은 날 방문의 정렬 기준을 명확히 했다. 일대다 조인으로 생기는 중복과 추적 누락의 영향을 점검하면서, 쿼리가 실행되는 것과 분석 기준이 정확한 것은 별개의 문제라는 점을 배웠다. SQL, 실행 출력, 해석을 연결해 GitHub에 정리했다.

결과물: [SQL README](../sql/README.md), [과제](../sql/assignments/), [분석 결과](../sql/results/analysis.md)

## WEEK 3 · AI Agent 학습

AI 코딩 에이전트를 활용해 요구사항을 코드로 구체화하는 과정을 학습했다. 대상 독자, KPI, 차트, 필터를 정하고 조인 키·중복 제거 기준·검산값을 함께 전달했다. AI가 만든 결과를 확인할 때는 화면 구성뿐 아니라 숫자의 계산 근거도 검토해야 한다는 점을 배웠다.

결과물: [AI 활용 구조](../web/README.md), [재현 프롬프트](../web/docs/prompts.md)

## WEEK 4 · AI Agent 결과물 및 최종 정리

호흡기 질환 그래프와 CareLens 대시보드를 최종 결과물로 정리했다. 지표·필터 테스트와 HTML 빌드를 수행하고 GitHub Pages로 공개했다. README와 회고를 보완하고, SQL·웹·최종 문서의 위치를 구분했다.

결과물: [대시보드](https://emem-kim.github.io/nano_dee/dashboard.html), [최종 결과 문서](final-report.md)

## 전체 학습을 통해 얻은 점

SQL로 데이터를 조회하는 것에서 끝나지 않고, 사용자가 필요한 답을 얻을 수 있도록 지표와 화면을 구성하는 과정까지 경험했다. AI 활용에서도 구체적인 요구사항과 검증 기준이 있어야 결과물의 품질을 판단할 수 있었다.

기존 백엔드·DB 개발 경험에 연결한다면 통계 API와 운영 대시보드에 적용할 수 있다. 앞으로는 정적 데이터 대신 실제 API의 데이터를 연결하고, 갱신·오류 상황에서도 올바른 지표를 제공하는 구조를 만들어 보고 싶다.
