# 웹 대시보드 강의 회고

[대시보드](https://emem-kim.github.io/nano_dee/dashboard.html)

강의를 들으면서 정리한 부분은 대시보드를 만들기 전 “누가, 얼마나 자주, 무엇을 결정하기 위해 보는가”를 정해야 한다는 점이었다. 숫자와 차트를 단순히 많이 넣는 것보다는 보는 이가 원하는 답을 정확히 얻을 수 있는 지표를 선택하는 것이 중요하다는 것을 느꼈다.

과제를 통해서는 같은 데이터라도 무엇을 기준으로 집계하느냐에 따라 전달하는 의미가 달라진다는 점을 배웠다. 예를 들어 청구 건수와 환자 수는 서로 다른 지표이고, 같은 환자가 여러 번 방문할 수 있으므로 구분해서 봐야 한다. 차트도 보기 좋은 모양을 고르는 데서 끝나는 것이 아니라, 항목 간 비교인지 시간에 따른 변화인지에 맞춰 선택해야 한다는 점이 기억에 남았다.

좋았던 점은 SQL로 조회한 데이터를 웹 화면과 연결해 다른 사람도 볼 수 있는 결과물로 만들 수 있었다는 것이다. 쿼리 결과를 표로 확인하는 것에서 나아가 필터와 차트를 통해 살펴보니, 데이터를 어떻게 전달할지도 개발 과정의 중요한 부분이라는 생각이 들었다. AI를 활용할 때도 단순히 “대시보드를 만들어 달라”고 요청하기보다 대상 독자, 지표의 계산 기준, 필요한 기능을 구체적으로 정리하는 것이 중요했다.

내가 주로 다뤄 온 백엔드와 데이터베이스 개발에 적용한다면 서비스 운영 현황을 확인하는 대시보드를 만들어 보고 싶다. API 요청 수, 오류율, 응답시간을 함께 보여주고 기간이나 API별로 확인할 수 있게 하면 어느 기능에서 문제가 생기는지 파악하는 데 도움이 될 것 같다. 이때도 수집할 수 있는 데이터를 전부 보여주기보다는 운영자가 실제로 확인하고 판단할 수 있는 지표부터 정하고 싶다.

아쉬운 점은 이번 결과물이 정해진 데이터를 보여주는 방식이라, 실제 서비스처럼 데이터가 계속 쌓이거나 바뀌는 상황까지 다뤄 보지는 못했다는 것이다. 다음에는 백엔드 API나 데이터베이스와 연결해 데이터 변경이 화면에 반영되는 과정까지 구현해 보고 싶다. 이번 강의를 통해 데이터를 저장하고 조회하는 기능뿐 아니라, 그 결과를 사용자가 이해하고 활용할 수 있게 만드는 과정까지 함께 생각하게 되었다.
